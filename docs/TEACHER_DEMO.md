# 给老师的 AI 演示与讲解

[项目首页](../README.md) · [AI 架构详解](AI_ARCHITECTURE.md) · [验证结果](VERIFICATION.md) · [DeepSeek 接入](DEEPSEEK_APPLICATION_20261114.md)

建议用 8～10 分钟讲清 AI 如何读取业务、找出关键原文，并把可核对的证据交给操作人员。

## 演示准备

按[部署说明](../services/private-assistant/README.md)启动独立环境。本机阶段 2 入口为 `http://127.0.0.1:5181/#/ai/knowledge`，其他机器按实际配置。

- 在仓库根目录运行 `pwsh -NoProfile -File .\scripts\test-stage2-demo.ps1`。检查两库监听、前端、后端鉴权、代理鉴权响应和知识服务数据库健康。私有 PostgreSQL 端口改过时追加 `-PostgresPort <端口>`。通过后再用演示账号做一次业务查询和原文查看。
- 准备两个演示账号。用“系统管理员”展示工作台的全仓库存查询，再切到“质检员 / 质量与知识库”账号 `lamp_quality` 展示私有知识。提前确认质检员已导入[10 份合成资料](../services/private-assistant/examples/lamp-showcase/README.md)。
- 提前检查文档索引、图谱和引用原文，完整建图提前完成。
- 双向追溯使用有用料记录的独立台灯演练库。当前阶段 2 资料演示库没有完整的投入批与产出批关联。上台前按[追溯复现步骤](AI_MES_RESEARCH_20261113.md#第二轮追溯复现)准备；也可在讲稿中展示已核对的报工记录。
- 现场生成需要模型可用及资料处理同意。没有模型时可演示本地检索、原文、现有图谱和工作单；已有回答明确说明为回放。
- 增改删演示使用单独的小型临时资料，保留这套资料基线。
- 如需演示云工具，提前用独立账号与合成扫描件核对配置、网络、额度及麦克风权限。离线课堂可展示本轮实测流程或讲稿中的操作路径。

## 1. 讲目标和架构（约 1 分钟）

> 这个项目在台灯 MES 上增加 AI 助手。制造现场的问题有两类：一类是库存、工单和订单的当前状态，另一类是产品、装配和检验资料中的知识。我分别接入业务工具和私有知识服务，再通过研判工作单连接起来。展示重点是回答从哪里来，以及建议怎样进入业务流程。

打开[架构图](AI_ARCHITECTURE.md)，指出 Vue、Spring Boot、Python，以及 MySQL 和每用户 PostgreSQL 各自保存什么。

## 2. 业务 AI：查询与准备办理（约 1 分钟）

登录“系统管理员”，打开 AI 工作台并提问：

```text
哪些物料低于安全库存？缺口是多少？
```

可追加“当前设备故障影响哪些任务？”和“查看上周设备维修记录”。前者把故障、开放报修和当前工位任务并列，后者只展示指定时间段的在册设备报修。工位关联是排查线索，实际影响由现场核对。

### 可选加讲：批次双向追溯（约 1 分钟）

在独立台灯演练环境打开 AI 工作台，用系统管理员问两次：

```text
正查原料批次 LAMP-REH-20261025-M3 的去向
反查成品批次 C3-LP-20261030-001 用了哪些原料批次
```

两次都定位到报工单 `C3-WR-20261030-002` 和工单 `C3-WO-20261030-002` 的同一条用料记录，投入批记录用量为 **10 片**。反查还可看另一个投入批 `LAMP-REH-20261025-M4`。指出页面上的追溯记录 ID，用它核对两个方向的证据。这里展示的是直接用料关系，用量按物料单位显示，记录口径包含报废量。

选择演示库中实际存在的工单，再询问开工前置条件。展示办理卡片时说明目标与条件，是否确认执行按现场安排决定。

讲解：模型输出结构化计划，工具读取实时数据，写操作受权限、预览确认和领域事务控制。**20 项查询加 19 项办理**是后端能力目录；前端 21 个快捷办理入口是另一统计口径。

## 3. 文档 RAG：回到原文（约 2 分钟）

退出管理员账号，选择“质检员 / 质量与知识库”登录。进入“我的知识”，选择文档方式：

```text
L100 当前生效的驱动板是什么？
```

打开来源，展示文件名、版本、位置和原文 `DRV-07`，再看资料列表的五种格式。

> 文件解析后保留原文位置，本地嵌入模型把片段变成 512 维向量。问题也转成向量，在本人库中找相关原文。有有效资料且允许处理时，再交给大模型综合回答。老师可以顺着引用回到对应版本。

再用“L100 单台使用几个 DRV-07，在哪道工序使用？”展示物料清单排进前四条摘录。在同一套七道指定出处题中，完整证据进入前四条的题目由 2 道增加到 7 道。

检索得分不等于答案准确率，有效引用编号也不等于逐句正确性证明。

可以接着问“L100 和 L900 的驱动板有什么不同？”质检演示资料只有 L100 的依据时，页面保留对应原文，指出 L900 缺证据，并暂停生成对比结论。[调研与离线评估](AI_MES_RESEARCH_20261113.md)

### 可选加讲：扫描件进入 RAG（约 1 分钟）

准备一张合成检验卡，上面写“L100 调光检验观察低、中、高三个档位。驱动板为 DRV-07。”在“我的知识”点击“扫描件识别”，选择图片或 PDF 对应页，确认发送。对照扫描原页，把型号、档位或单位的识别错误改对，勾选已核对再入库。索引完成后问“L100 调光检验观察哪些档位？”，点引用中的“查看扫描原页”。

> 扫描件由 OCR 补上可检索的文字。校对结果和原件一起管理，提问后还能回到对应版本和页码。内外资料分别使用，公开网页可单独查阅，语音转写填入草稿后由人确认。

## 4. GraphRAG：跨文件关联（约 2 分钟）

选择融合方式：

```text
L100 的驱动板、装配工序和检验规范怎样关联？请给出依据。
```

切到图谱，搜索 `L100`，查看节点、关系及来源：

```text
L100 → DRV-07 → PROC-DIM → QC-DIM-01
```

> 这条链路分散在产品、BOM、装配和检验资料里。LightRAG 抽取关系，Apache AGE 保存图谱，融合问答结合关系线索和文档片段。关键结论仍需原文支持。自动方式当前按问题特征选文档或融合，用户也可以手动选择。

节点和关系数以页面实际显示为准。路径探索只覆盖当前图中的有限步数。

## 5. 两个反例（约 1 分钟）

```text
ECO-L100-02 批准了吗？现在能把 L100 的 DRV-07 换成 DRV-08 吗？
```

核对“候选变更未批准”和“当前配置 DRV-07”，说明版本与适用范围。

```text
L100 的色温误差合格限值是多少？
```

资料未提供数值，应说明缺少依据或展示相关原文，不能补造阈值。

## 6. 工作单：从答案到交接（约 1 分钟）

保存一条有效答复，补充现场备注及“核对当前物料版本”“核对适用检验规范”两项人工核对。打开来源、导出交接稿，再转为业务助手草稿。

> 工作单保存原答复和版本依据，人员补现场信息。导出或转业务前复核来源，过期资料提示重新核对。转交只准备草稿，后续办理仍需预览和确认。

## 老师可能追问

| 问题 | 建议回答 |
|---|---|
| RAG 与普通聊天的区别？ | 先检索本人有效资料，再基于命中片段回答，能够回到具体文件版本和位置。 |
| 为什么还要图谱？ | 产品—物料—工序—检验关系能帮助定位跨文件证据；直接配置问题仍可用文档检索。 |
| DeepSeek 新接口接在哪？ | 扫描 OCR 在入库前，公开搜索和正文读取在查阅窗口，语音转写在提问前，朗读在答复后。调用前会显示或明确本次发出的内容。 |
| 批次追溯用知识图谱吗？ | 工作台按 MES 的用料追溯记录查直接的投入与产出。两个方向可通过同一追溯 ID、工单号和报工单号交叉核对。 |
| 为什么分两个后端？ | Spring Boot 保留业务权限与事务，Python 接入解析、嵌入、LightRAG 和本地人脸模型。 |
| 怎样隔离私有知识？ | Spring 取认证身份并签名，Python 打开本人独立数据库、角色和目录。 |
| 模型能直接修改数据库吗？ | 它选择已注册能力，写入由后端校验、预览确认和领域服务完成；知识服务不能执行业务。 |
| 更新后旧答案怎么办？ | 新索引就绪后发布新版，旧引用失效，后续问答和工作单转交重新核对来源。 |
| 模型不可用怎么办？ | 展示本地原文检索、现有图谱、已保存工作单及普通 MES；明确哪些是回放。 |
| 做了微调或自研大模型吗？ | 当前是模型、检索、图谱与 MES 的工程集成，没有训练自研大模型。 |
| 已经全部验收了吗？ | 按验证文档说明本轮检查；第二位参与者、错误脸及课堂分工等仍需本人现场核验。 |

全部演示资料为合成教学样例。离线检索、模型生成样例、程序测试与真人认证分别说明；Dify 未部署，现有流程由业务编排和工作单衔接。成员贡献按本轮真实工作说明。

需要展开实现时，直接打开[架构说明末尾的代码入口](AI_ARCHITECTURE.md)，把设计对应到源码。
