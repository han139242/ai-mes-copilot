## 使用

本人在账号安全验证密码、明确同意后点击“开始自动采集”；登录页直接点“刷脸登录 · 无需账号”，不必填写用户名。页面和可关闭的语音依次提示正面、随机左右轻转头。每步连续两次通过本机服务端姿态、清晰度及与正面的一致性检查才采集，三步完成自动提交。转头过大会当场提示回正一点；采集质量错误不计为已知账号的身份错误。取消、切换页面、超时或登录会话改变都会停止后续采集并释放摄像头。小屏弹窗内部滚动，取消与重试按钮保留在可见底部。

本轮没有实现眨眼判定，也没有新增远端模型、浏览器插件或依赖。动作检查仍为基础交互核验，不宣称专业活体认证。采集画面不作为缩略图长期停留；原件不落盘，不发送给大模型。

## 服务边界

- 免账号登录使用 `POST /api/auth/face/identify-challenge`、`/identify-frame`、`/identify-login`；旧账号加人脸接口保留兼容。录入预检 `/frame-enroll` 和管理入口仍要求 JWT，录入挑战来自先前的密码确认。
- Java 从有效 MES 账号取得完整候选，超过100个整体拒绝并保留密码入口。浏览器传入账号、UID或候选列表均不能改变识别范围。只查询已存在的私有库，不给未录入者批量建库。任一必要库不可用时整体失败，不通过漏算候选完成登录。
- 独立 SQLite 只记录45秒挑战、随机动作、候选ID和模板版本，不存图片、探测向量或模板副本。专用签名协调上下文仅允许三个识别动作，不能访问用户资料或创建用户0数据库。
- 参数检查后按IP和挑战限流，最多两项并行识别；候选扫描有截止时间、数据库连接和查询超时。429自动退避。预检只返回合格与提示，不返回候选、相似度或令牌。
- 最终先验证三帧姿态、一致性、重复画面和单次挑战，再用同一归一化聚合向量排名全部候选；最高分须达0.5，领先第二名至少0.08。歧义拒绝，不默认选第一个或管理员。这是本项目初始策略，未经真人样本标定，不代表误识率保证。
- 排名、最终验证、录入和重置共用跨进程数据库协调锁；评分前后复查所有模板版本，变化就重新开始。成功后复核原MES账号停用、锁定与删除状态，再签发原JWT。预检成功不等于认证成功。
- 最终请求已发送后关闭窗口只停止界面等待；录入状态以账号安全刷新结果为准，不能将关闭窗口当作撤销已完成的保存。
