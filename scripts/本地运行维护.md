# 本地运行维护

在仓库根目录使用 PowerShell：

```powershell
.\scripts\manage-local.ps1 -Action start
.\scripts\manage-local.ps1 -Action status
.\scripts\manage-local.ps1 -Action restart -Service backend
.\scripts\manage-local.ps1 -Action stop
```

`start` 复用同一配置、同一身份且受监管的健康进程。`stop` 默认只停前后端，数据库保留；不会按端口强杀其他进程。修改配置或丢失监管时使用单服务 `restart`。

后端在独立构建目录完成打包、配置的测试与临时端口启动检查后，才切换正式服务。构建或启动检查失败时，旧服务保留。打包日志不能代替测试结果；示例配置的六组测试覆盖鉴权、异常处理与缓存故障，不代表完整业务回归。

Redis 停止时，连接等待默认为 500 毫秒、命令等待为 750 毫秒。令牌撤销检查确认缓存故障后冷却 5 秒，继续使用现有进程内黑名单；本机已注销令牌始终优先拦截。探测锁拥塞或线程中断返回 HTTP 503，禁止放行业务，也不应清除登录。此降级用于本地单实例；多实例部署仍需共享且可靠的撤销存储。

工作台把连接失败与管理员关闭 AI 分开显示，连接失败每 15 秒重新检查状态；不会自动重放聊天或业务写操作。恢复同步不能覆盖发送中的消息。通过 Windows 项目目录联接运行入口也会执行真实操作，不再静默退出。

前后端意外退出最多恢复两次；主动停止不会恢复。运行记录、退出码和日志位于 `tmp/local-runtime/`，需先查日志再处理，禁止反复调用旧的强杀脚本。

本机私密配置是 `tmp/local-runtime.json`，结构参考 `local-runtime.example.json`。环境脚本提供密钥与数据库凭据；配置和日志不入库。其他机器必须先核对自己的业务库、端口、数据目录和必要表，不能照抄本机数据位置。

本轮本机业务库在 3311，测试库在 3307，历史 3306 实例未调整。MySQL 使用持久错误日志，不在正常启动时执行账号初始化 SQL。数据库不会被强制结束；显式关闭需要已有管理员凭据，未提供时保留运行。

不要让多个开发任务绕过入口执行 `taskkill` 或直接启动同端口服务；命名互斥只保护这个统一入口，不能阻止其他程序直接终止进程。
